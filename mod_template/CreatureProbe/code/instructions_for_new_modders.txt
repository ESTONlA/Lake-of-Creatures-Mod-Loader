Put your GML files in subfolders that reflect what they patch.

Suggested layout:
- hooks/ for script hooks
- objects/ for object event replacements
- functions/ for newly created functions

Files are loaded recursively and referenced by relative path, for example:
context.HookFunctionFromFile("hooks/example_hook.gml", "scr_real_target");

Visual Studio Code has GML highlighting extensions, which makes this much less painful.
